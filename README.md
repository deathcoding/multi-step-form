# Multi-step onboarding form

Демонстрационное приложение: многошаговый onboarding-опросник на React с валидацией по шагам, хранением прогресса в браузере и финальным экраном успеха.

## Возможности

- **Пять шагов**: личные данные → роль и локация → оборудование → комментарии и мерч → сводка и «отправка».
- **Валидация**: на каждом шаге своя Zod-схема и `react-hook-form` (`zodResolver`).
- **Состояние**: накопление данных в Redux Toolkit (`formSlice`), текущий шаг и флаг успешной отправки.
- **Персистентность**: `redux-persist` сохраняет состояние в **localStorage** (ключ `persist:onboarding`), чтобы можно было закрыть вкладку и продолжить позже.
- **Условные поля**: язык программирования только для департамента «Разработка», часовой пояс — только для Remote, количество мониторов — если отмечен запрос монитора (доп. проверки в `superRefine`).

## Как устроен поток данных

1. Пользователь заполняет шаг → **submit** вызывает `dispatch(nextStep(partialData))`: данные **мержатся** в `formData`, `currentStep` увеличивается (не выше последнего индекса из `wizardStepMeta`).
2. «Назад» → `prevStep()` уменьшает индекс (не ниже нуля).
3. На сводке «Отправить заявку» → `completeSubmission()`; показывается `SubmissionSuccess`.
4. «Начать заново» → `resetForm()` возвращает slice к `initialState` и очищает сохранённое состояние после регидации persist.

Локальное состояние полей на шаге — в **react-hook-form**; начальные значения берутся из Redux при монтировании компонента шага (при возврате назад шаг монтируется заново — значения подтягиваются снова).

## Как устроены шаги

Экран мастера собирается из двух списков, которые должны совпадать по **количеству элементов** и по **порядку** (индекс 0 — первый шаг, индекс 1 — второй и т.д.):


| Файл                                       | Что там лежит                                                                |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| `wizard/wizardStepMeta.ts`                 | Только текст для прогресса: полное название и короткая подпись в индикаторе. |
| `wizard/stepsConfig.ts` → `stepComponents` | Реальные компоненты страниц (форма или сводка).                              |


Если длины списков разойдутся, при старте приложения будет выброшена ошибка — так проще поймать опечатку, чем показывать пользователю «не тот» шаг.

**Важно про типы и сводку.** Данные анкеты набираются на шагах **1–4** и попадают в Redux через `nextStep`. Шаг **5** (`Step5Summary`) только **читает** уже собранное и не добавляет новых полей в тип `OnboardingFormData`. Поэтому:

- если вы добавляете экран **с новыми полями** до сводки — нужно описать их в Zod-схеме шага и включить тип шага в `state/types.ts`;
- если добавляете ещё один экран **после** набора данных — решите, это форма (пишет в Redux) или только информационный экран, и обновите сводку при необходимости.

### Чеклист: добавить новый экран в цепочку

1. **Подписи в прогрессе** — добавьте объект `{ title, shortLabel }` в массив `wizardStepMeta` в том месте, где должен стоять шаг по порядку.
2. **Страница шага** — создайте папку в `steps/` с компонентом и `schema.ts` (по образцу существующих шагов).
3. **Подключение в мастере** — импортируйте компонент и вставьте его в массив `stepComponents` в `stepsConfig.ts` **на ту же позицию**, что и строка в `wizardStepMeta`.
4. **Типы и финальный экран** — если шаг отдаёт новые поля в Redux, расширьте `OnboardingFormData` в `state/types.ts`; если эти поля нужно показать пользователю на сводке — добавьте строку в список в `Step5Summary.tsx`.

## Что это за «отправка»

В текущей версии нет HTTP API: финальное действие только переводит UI в состояние успеха и опирается на **persist** для данных в браузере.
